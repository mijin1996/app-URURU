# coding-rules.md — 코드 작성 지침(게임 · 앱 · 웹 공통)

> [기본 원칙 4] 모든 프로젝트에 기본으로 쓰는 규칙이에요 (원문 그대로).

## 0. 작업 순서
1. (TDD방식) 일단 돌아가게 만든다
2. 반복 코드가 생기거나 클래스가 커지면 정리한다
3. 정리할 때 아래 원칙을 체크한다

## 1. 기본 원칙 (모든 코드)
* **KISS**: 단순하게. 더 쉬운 방법은 없나?
* **YAGNI**: 지금 필요 없는 기능은 만들지 않기
* **DRY**: 복붙 1번 이상이면 함수로 묶기
* **PIE**: 이름만 보고 무슨 일 하는지 알 수 있게

## 2. 클래스 설계 (SOLID)
* **S (SRP)**: 클래스 하나는 한 가지 일만
* **O (OCP)**: 새 기능은 기존 코드 고치지 말고 추가로
* **L (LSP)**: 자식은 부모 자리에 넣어도 문제없이
* **I (ISP)**: 안 쓰는 기능 억지로 구현하게 하지 않기
* **D (DIP)**: 구체 클래스 말고 인터페이스에 기대기
* **체크**: 이 클래스를 고칠 이유가 2개 이상이면 쪼갤 때!

## 3. 폴더 · 모듈 설계
* **SDP**: 자주 바뀌는 코드가 안 바뀌는 코드를 사용하도록
* **ADP**: A와 B가 서로를 쓰는 순환 구조 금지
* 예시 폴더: Core(공통) / Data(저장·통신) / Gameplay(플레이어·적) / UI(화면 표시)

## 4. 실패 처리
* 실패해도 이상하지 않은 일은 **Result 패턴** (저장 파일 없음, 인터넷 끊김, 로그인 실패, 잘못된 입력)
* 절대 일어나면 안 되는 일(버그)은 **예외(Exception)**
* null 대신 실패 이유까지 같이 돌려주기

## 5. 코드 스타일
* **Allman**: 여는 중괄호는 다음 줄에 따로 (2026-10-20 미미). 단, 자바스크립트 `return {`는 같은 줄에
* **세미콜론(;) 뒤에는 항상 줄바꿈**: 한 줄에 `;`로 끝나는 문장(속성)은 하나만. 자바스크립트 문장과 CSS 속성 모두 (2026-10-13 미미)
* 주석은 "왜" 이렇게 했는지 적기
* bool 이름은 질문처럼: `isDead`, `hasKey`, `canJump`
* 함수 하나는 화면 한 장 안에
* 숫자 대신 이름: `5f` 말고 `moveSpeed`

## 6. 커밋 전 체크리스트
* ☐ 잘 돌아가나?
* ☐ 복붙 코드 없나?
* ☐ 클래스마다 역할 하나인가?
* ☐ 이름만 보고 뜻이 보이나?
* ☐ 실패할 수 있는 작업은 Result로 처리했나?
* ☐ 주석 달고 Allman 지켰나? 세미콜론 뒤에 줄바꿈했나?
* ☐ 안 쓰는 코드, 디버그 로그 지웠나?
