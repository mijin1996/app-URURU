# admin-guide.md — 운영자 사이트 사용·관리 안내

> 2026-10-21 만듦 · 같은 날 아이디 로그인·주소 분리로 다시 씀.
> 신고를 확인하고 경고·정지를 주는 **운영자 전용 사이트**예요. 사용자 앱과 주소도, 계정도 따로예요.

## 1. 등급별 들어가는 곳 (주소 모음)

> 주소를 잊으면 여기서 찾아요. 크롬 즐겨찾기 폴더 "우르르"에 넣어 두면 편해요.
> 앱 화면 어디에도 운영자 사이트로 가는 버튼·링크는 없어요 (일반 사용자가 운영자 입구를 찾지 못하게).

| 등급 | 들어가는 곳 | 주소 | 로그인 | 들어가서 할 수 있는 것 |
|---|---|---|---|---|

- 일반 운영자 · 총관리자 · 최종관리자는 **주소도 로그인 화면도 같아요.** 로그인한 아이디의 등급에 따라 보이는 탭과 버튼이 달라요 (일반 운영자에게는 "운영자 관리" 탭이 없음).
- 권한은 화면이 아니라 서버 규칙(`firestore.rules`)이 막아요. 화면을 고쳐도 등급 밖의 일은 서버가 거절해요.
- 지금 코드의 등급은 **운영자 · 총관리자 2개**예요. 최종관리자와 2단계 승인은 `admin-roles.md`대로 만들 예정.

### 내 컴퓨터에서 열기 (개발 · 임시)

`npm run dev`를 켠 그 컴퓨터에서만 열려요. **데이터는 진짜 서버**라 처리 · 삭제가 실제로 적용돼요.

| 무엇 | 주소 | 켜는 명령 |
|---|---|---|
| 사용자 앱 | http://localhost:5173 | `npm run dev` |
| 운영자 사이트 | http://localhost:5173/admin.html 또는 http://localhost:5180/admin.html | `npm run dev` 또는 `npm run dev:admin` |

### 올리기 · 코드

| | 사용자 앱 | 운영자 사이트 |
|---|---|---|
| 올리기 | `npm run deploy:web` (dist/ → Hosting `app`) | `npm run deploy:admin` (dist-admin/ → Hosting `admin`, `.firebaserc` 12줄의 사이트 이름) |
| 코드 | `src/` (admin 제외) | `src/admin/`, `admin.html`, `styles/admin.css` |
| 로그인 저장 | 앱 것 | 따로 (Firebase 앱 이름 "admin") — 앱에 로그인돼 있어도 운영자 사이트는 따로 로그인, **탭을 닫으면 로그아웃** |

## 2. 운영자 아이디

- 처음 등록: 성명 · 닉네임 · 생년월일 · 이메일(연락용) · 아이디. 그 다음부터는 아이디만으로 로그인.
- 12자리: 대문자 · 소문자 · 숫자 · 특수문자 `! @ # $ % ^ & . ~ `` ` 가 각각 1개 이상 (대소문자 구분).
- **총관리자가 발급해야만** 생겨요. 발급한 순간 화면에 딱 한 번 보이고, 서버에는 아이디 자체가 아니라 암호화한 값(SHA-256)과 앞 3자리·뒤 3자리만 남아요.
- 한 아이디로 한 사람만 등록할 수 있어요 (등록하면 "사용함"으로 바뀜). 아직 안 쓴 아이디는 "발급 취소"로 지울 수 있어요.
- 처리 기록에는 **성명 · 아이디 일부** 로 남아요. 예: `김미미 · Ab3…9x!`

## 3. 처음 한 번: 총관리자 만들기

1. Firebase 콘솔 → Authentication → 로그인 방법 → **이메일/비밀번호** 사용 설정 (운영자 아이디가 이 방식으로 로그인해요).
2. 운영자 사이트 주소 만들기: 터미널 `npx firebase hosting:sites:create <이름>` (`ururu-admin`은 못 씀) → `.firebaserc` 12줄에 그 이름.
3. Authentication → 설정 → 승인된 도메인에 `<이름>.web.app` 추가 (구글 첫 설정 팝업용).
4. 규칙 올리기: `npx firebase deploy --only firestore`
5. 운영자 사이트 올리기: `npm run deploy:admin`
6. 운영자 사이트 아래쪽 **"총관리자 첫 설정 (구글, 처음 한 번만)"** → `unidevpeer@gmail.com` 으로 로그인 → 역할 **총관리자**로 아이디 발급 → 복사해서 안전한 곳에 보관.
7. 로그아웃 → **처음 등록** 탭 → 성명 · 닉네임 · 생년월일 · 이메일 · 방금 받은 아이디 → 등록.
8. 이후로는 **로그인** 탭에 아이디만 넣으면 돼요. (구글 첫 설정 이메일은 `firestore.rules`의 `isBootstrapOwner()`에 적혀 있어요. 다 끝나면 지워도 돼요.)

## 4. 다른 운영자 추가

1. 총관리자로 로그인 → **운영자 관리** 탭 → 역할(운영자/총관리자)·메모(누구에게 줄지) → **아이디 발급**.
2. 나온 아이디를 그 사람에게 직접 전달 (다시는 볼 수 없어요).
3. 그 사람이 운영자 사이트 → **처음 등록** → 성명 · 닉네임 · 생년월일 · 이메일 · 아이디.
4. 그만두면 운영자 명단에서 **권한 회수**.

## 5. 신고 목록

- 새 신고가 맨 위. 날짜·시간, 사유, 같은 사람이 신고된 횟수.
- 신고한 사람이 붙인 것: 길게 눌러 신고한 메시지, 자세한 내용(500자), 사진 1장.
- 신고한 사람 · 신고당한 사람 정보: 사진, 닉네임, @아이디, 이메일, 생년월일(나이), 국가, 지역, 위치 공유, 태그, 가입일, 제재 상태, UID.
- 버튼: **처리 완료 · 경고 · 7일 정지 · 영구정지 · 정지 풀기** → 누가 언제 무엇을 했는지 처리 기록에 쌓여요.

## 6. 회원 관리

- 회원 목록(최근 가입 순, 50명씩 더 보기)과 검색(닉네임 앞부분 · @아이디 · UID). 회원을 누르면 사진·이메일·생년월일·국가·제재까지 다 보여요. — 운영자 모두
- **회원 삭제는 총관리자만.** 아이디(@handle)를 똑같이 입력해야 "영구 삭제"가 눌려요.
- 지우면 Firestore에서 바로 지워지는 것: 프로필, 비공개 정보(이메일·생년월일), 아이디, 친구, 주고받은 메시지, 좋아요, 스토리(+좋아요), 위치, 입력 중, 차단, 소리 울리기.
- 남기는 것: 경고·정지 기록(moderation)과 신고 기록 — 같은 계정으로 다시 가입해도 제재를 피하지 못하게.
- 누가 언제 누구를 지웠는지 **삭제 기록**(deletions)에 남고, 고치거나 지울 수 없어요.
- 로그인 계정(Authentication):
  - 무료 모드: 서버 함수 없이는 다른 사람의 로그인 계정을 지울 수 없어서 Authentication 목록에 남아요. 데이터는 없어서, 그 사람이 다시 들어오면 가입 화면부터 시작해요. 필요하면 Firebase 콘솔 → Authentication에서 직접 삭제.
  - 서버 함수 모드(Blaze, `VITE_SERVER_FUNCTIONS=true`): `adminDeleteUser` 서버 함수가 로그인 계정까지 지워요.

## 7. 총관리자 여러 명

- 총관리자도 여러 명 둘 수 있어요: 운영자 관리 → 역할 **총관리자**로 아이디 발급.
- 마지막 남은 총관리자는 권한 회수가 안 돼요 (아무도 아이디를 발급 못 하게 되니까).
- 구글 첫 설정 이메일(`isBootstrapOwner()`)도 여러 개 적을 수 있어요.

## 8. 보안 (firestore.rules)

- 운영자 = 이메일/비밀번호로 로그인 + `admins/{uid}` 문서가 있는 사람 (`isAdmin()`).
- 신고·이메일·제재는 운영자만 읽고 바꿀 수 있고, 바꿀 때 반드시 내 이름·아이디 일부를 남겨야 해요 (`signedBy()`).
- 발급·명단·회수는 총관리자만 (`canIssueIds()`), 회원 삭제도 총관리자만 (`canPurge()`).
- 운영자 사이트는 검색엔진에 안 나오고(noindex) 다른 사이트 안에 끼워 넣을 수 없어요 (firebase.json 헤더).
