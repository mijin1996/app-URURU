# admin-roles.md — 운영자 권한 흐름 (B안: 무료 모드, 메일 없이 운영자 센터 안에서 승인)

> 2026-10-21 미미와 정함. **설계 문서 (아직 코드에 적용 안 됨).**
> 지금 코드는 "총관리자가 아이디 발급 → 받은 사람이 처음 등록" 방식이에요 (docs/guides/admin-guide.md).
> 이 문서대로 바꾸면 발급 방식과 구글 첫 설정 경로는 없어져요.

## 1. 등급

| 등급 | 몇 명 | 할 수 있는 일 |
|---|---|---|
| 최종관리자 (root) | 딱 1명 | **운영자 사이트의 모든 일** — 운영자 · 총관리자가 하는 일 전부 + 모든 신청 최종 승인 · 누구든 권한 회수 · 최종관리자 넘겨주기 |
| 총관리자 (owner) | 여러 명 | 자기 소속 운영자 신청 1차 승인 · 자기 소속 운영자 권한 회수 · 회원 삭제 |
| 운영자 (admin) | 여러 명 | 신고 처리(경고·정지·영구정지) · 회원 보기 |

- 운영자는 꼭 한 명의 총관리자에 소속돼요 (신청할 때 고름, 나중에 못 바꿈. 바꾸려면 회수 후 다시 신청).
- 최종관리자는 **제한 없이 모든 일**을 할 수 있어요 (규칙에서 `isRoot()`는 운영자 · 총관리자 권한을 모두 포함). 못 하는 건 자기 자신 회수뿐 — 바뀔 때는 넘겨주기로만.

## 2. 신청 → 승인 흐름

```
[신청자]  운영자 사이트 → "운영자 신청"
          성명 · 닉네임 · 생년월일 · 이메일 · 역할(운영자/총관리자) · 소속 총관리자(운영자일 때)
          + 아이디 12자리를 이 화면에서 만들어 줌 → 본인만 복사해서 보관 (서버에는 암호화 값만)
              │
              ▼
   운영자 신청?  ──예──▶  [소속 총관리자] 승인 대기 탭 → 승인 / 거절      (1단계)
              │                         │ 승인
              │아니오(총관리자 신청)      ▼
              └──────────────▶  [최종관리자] 승인 대기 탭 → 승인 / 거절    (최종)
                                        │ 승인
                                        ▼
          신청자가 처음에 만든 아이디로 로그인 → 바로 운영자 센터 사용
```

- 신청하는 순간 로그인 계정은 만들어지지만, **최종 승인 전까지는 아무 데이터도 못 봐요** (규칙: `admins/{uid}` 문서가 있어야 운영자).
- 신청자는 같은 아이디로 로그인하면 "승인 대기 중 (1/2)", "거절됨" 같은 상태만 보여요.
- 아이디는 신청자 본인만 알아요. 승인하는 사람도, 서버도 아이디 원문을 모르니 전달할 필요가 없어요.
- 승인은 반드시 **본인 아이디로 로그인한 상태에서** 운영자 센터의 버튼으로만 돼요.
- 거절할 때는 사유를 적을 수 있고, 거절된 신청은 다시 승인할 수 없어요 (새로 신청).
- 30일 동안 처리되지 않은 신청은 만료로 보여요.
- 모든 단계(신청·승인·거절·회수)는 **누가 언제** 했는지 `김미미 · Ab3…9x!` 모양으로 기록돼요.

## 3. 최종관리자 정하기 (코드에 적지 않음)

- 최종관리자가 누구인지는 Firestore 문서 `config/root` 하나에 적어요: `{ uid, since }`
- **처음 한 명:**
  1. 최종관리자가 될 사람이 운영자 사이트에서 "총관리자"로 신청 (아이디 만들어서 보관)
  2. Firebase 콘솔 → Firestore에서 직접:
     - `config/root` 문서 만들기 → `uid` = 그 사람의 신청 문서 uid
     - 그 신청을 "승인됨"으로, `admins/{uid}` 문서 만들기 (role: owner)
  3. 콘솔은 Firebase 프로젝트 주인만 들어갈 수 있어서, **"프로젝트 주인 = 최고 권한"** 이 돼요.
- **바꿀 때 (넘겨주기 2단계):**
  1. 지금 최종관리자가 운영자 센터에서 다음 사람(이미 총관리자인 사람)을 지정
  2. 지정받은 사람이 자기 아이디로 로그인해서 "수락" → 그때 바뀜 (그 전에는 취소 가능)
- **회사를 팔 때:** Firebase 콘솔 → 프로젝트 설정 → 사용자 및 권한에서 프로젝트 소유권을 넘기고, 운영자 센터에서 최종관리자를 넘겨주면 끝. 코드는 고칠 게 없어요.
- **최종관리자가 연락이 끊기면:** 프로젝트 주인이 콘솔에서 `config/root.uid`를 직접 바꿔요.

## 4. 권한 회수

- 총관리자 → 자기 소속 운영자만 회수
- 최종관리자 → 누구든 회수 (자기 자신은 못 함, 넘겨주기로만 바뀜)
- 총관리자를 회수할 때 그 밑의 운영자가 있으면, 먼저 다른 총관리자 소속으로 옮기거나 같이 회수해요.

## 5. 서버에 저장되는 것 (Firestore)

| 문서 | 내용 | 누가 읽나 | 누가 바꾸나 |
|---|---|---|---|
| `adminRequests/{uid}` | 성명·닉네임·생년월일·이메일·역할·소속 총관리자·상태·단계 기록·idHash·idMask | 본인, 소속 총관리자, 최종관리자 | 생성: 본인 / 1단계: 소속 총관리자 / 최종: 최종관리자 |
| `admins/{uid}` | 승인된 운영자 (위 정보 + role + ownerUid) | 운영자 | 최종관리자만 만듦 · 회수 |
| `config/root` | 최종관리자 uid · 넘겨주기 대기 | 운영자 | 최종관리자 (넘겨주기), 콘솔 |

- 상태(status): `waitingOwner` → `waitingRoot` → `approved` / `rejected`
- 규칙에서 지킬 것: 상태는 순서대로만, 1단계는 `ownerUid` 본인만, 최종은 `config/root.uid` 본인만, 기록에는 내 이름·아이디 일부(`signedBy`).

## 6. 나중에 Blaze(A안)로 바꾸면

- 흐름과 기록은 그대로, **알림 메일만 추가**: 신청이 오면 승인할 사람에게, 승인되면 신청자에게 메일.
- 메일의 버튼은 운영자 센터 승인 화면을 여는 것까지만 (로그인 후 직접 눌러야 승인).
