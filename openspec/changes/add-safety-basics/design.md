# Design

## Context

- 구글 플레이 사용자 생성 콘텐츠 정책: 약관 동의, 신고, **1:1 메시지가 있으면 차단 필수**, 꾸준한 관리. 계정 삭제 정책: 앱 안 + 웹 링크.
- 앱인토스 채팅 기준: 신고·차단, 계정 제재, 신고 처리 절차, 운영 약관 제출. 민감정보(위치)는 명시적 동의.

## Goals / Non-Goals

**Goals:** 두 스토어 공통 안전 장치를 한 번에.
**Non-Goals:** 자동 필터, 관리자 앱.

## Decisions

### D1. 차단은 신고와 따로
- 신고는 운영자에게 알리는 것, 차단은 나와 그 사람 사이를 끊는 것. 구글은 둘 다 요구해요.
- 서버 `blocks/{a_b}` + 보안 규칙에서 서로 읽기 거절 (`add-real-server` D3과 같은 자리).

### D2. 약관 문서는 md로 쓰고 웹에 올림
- `docs/policy/*.md` → Firebase Hosting으로 웹 페이지. 앱 안 "보기"와 스토어 등록 칸에 같은 주소를 써요 (DRY).

### D3. 신고 처리 운영
- 서버 함수가 신고를 받으면 운영자 메일로 알림. 처음엔 Firebase 콘솔에서 확인·제재. 절차는 `docs/policy/report-handling.md` (24시간 안 확인, 반복 위반 영구 정지).

### D4. 위치 동의는 기기 권한 창보다 먼저
- 기기 권한 창은 한 번 거절하면 다시 띄우기 어려워서, 우리 동의 창으로 이유를 먼저 설명해요.

## Risks / Trade-offs

- [운영자가 한 명] → 신고 메일 알림 + 처리 기한을 문서에 적어 지키기
- [약관 내용은 법률 문서] → 초안은 만들되 출시 전 전문가 검토 권장
